Broadcast Schema v2

Common tables are used by every channel. A count of broadcast.delivery is how many notifications a user was sent. broadcast.push_template and broadcast.push_device_token are push only, from the push guide. Email, SMS and WhatsApp get their own extra tables later.

Table groups

Masters

app is PUNEZP, JIJAU or TICKLINKS. broadcast.channel is push, email, SMS or WhatsApp. broadcast.status is the shared send status from the push guide.

Template and message

broadcast.template is the wording for one channel and one version. broadcast.message is one send: app, channel, template and schedule. It does not store title, body or a button.

Delivery

One row per user per send, for every channel. This is the place that answers how many notifications a user was sent. The push worker updates status, error and sent_at here.

In-app page

One card per user, template code and calendar day. A later send the same day updates placeholders. The next day inserts a new row. Message and delivery still get a new row every time.

Push only

broadcast.push_template holds the FCM data, web click URL and target devices. broadcast.push_device_token is one token per Android, iOS or web install. Email, SMS and WhatsApp do not use these tables.

Design notes

  1. How many notifications a user was sent is COUNT(*) from broadcast.delivery for that user_id. Channel comes from the message.
  2. broadcast.template is unique on (code, version, channel_id). The same code can have a push row now and an email row later. A used version is not edited. Insert the next version.
  3. A push send inserts one broadcast.message, one broadcast.delivery per user, and reads broadcast.push_template plus active broadcast.push_device_token rows. The worker writes status_id, error, rendered_title, rendered_body and sent_at on the delivery.
  4. The in-app screen reads broadcast.in_app_notification only. Same day is app_id + user_id + template_code + notice_date, using the calendar day in India. A same-day update clears read_date.
  5. latest_delivery_id is the last delivery that updated the card. Earlier sends that day stay on broadcast.message and broadcast.delivery.
  6. broadcast.status codes are 1 PENDING, 2 PROCESSING, 3 SENT, 4 PARTIALLY_SENT, 5 FAILED, 6 NO_DEVICE. Partially sent and No device are used by push. Email and SMS use the same list.
  7. device_platform on the token is android, ios or web. It is not broadcast.channel.
  8. There is no per-device result table yet. Several devices for one user are one delivery, with status Partially sent or No device, as in the push guide.
  9. Email, SMS and WhatsApp will add their own extra tables later. They still insert broadcast.message and broadcast.delivery.
  10. Old notification_* and broadcast_* tables are not altered. v1 of this diagram is unchanged.
