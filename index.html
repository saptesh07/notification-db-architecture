Broadcast Schema

Six tables for PUNEZP, JIJAU and TICKLINKS. Each broadcast.message row is one channel (channel_id). broadcast.delivery is one row per user, inserted with is_delivered and is_read false. Old notification and broadcast tables stay unchanged.

Table groups

Masters

app is PUNEZP, JIJAU or TICKLINKS. broadcast.channel is in_app, push, email, sms, whatsapp. broadcast.message.channel_id points here.

Event

broadcast.event_master.code is the stable name, such as FORGOT_PASSWORD or ADD_DIARY. broadcast.message_param lists the placeholders that event allows, such as $LinkId$.

Message

One row per channel. channel_id says which channel. The JSON is the title, body and token values for that channel. SMS and push for the same event are two rows. scheduled_at empty means send now.

Delivery

One row per user. Insert all recipients with both flags false. The worker sets is_delivered. The app sets is_read when the user opens it.

Message JSON

{
  "params": { "$LinkId$": "120", "$UserName$": "Asha" },
  "title": "New comment",
  "body": "Asha commented on your link"
}

Design notes

  1. Each broadcast.message row has one channel_id. SMS and push for the same event are two message rows, each with its own delivery rows.
  2. The JSON is the content for that channel only: title, body, and params. Email uses title as the subject.
  3. broadcast.message_param is the allowed list for an event. The values for one send live in message.params, so a deep link still has $LinkId$.
  4. Creating a send: insert one message per channel, then insert one delivery row per user with is_delivered = false and is_read = false. UNIQUE (broadcast_id, user_id).
  5. Inbox is delivery rows for that user_id whose message channel_id is in-app. is_read = false is unread.
  6. is_delivered stays false until that channel's send succeeds. fail_reason is set when it fails, so a waiting row and a failed row are not the same.
  7. address is for OTP, forgot-password and contact-us when the recipient is a mobile or email and not yet a user. Leave it empty when user_id is set.
  8. Provider keys (SMTP, FCM, SMS) stay in application config. They are not a table in this schema.
  9. Old notification_* and broadcast_* tables are not altered.
